## 技術說明

### FailBallChart — Fail Ball 分佈圖

使用 ECharts（`echarts-for-react`）繪製長條圖，顯示失效 BGA Ball Name 前 10 名，並提供 **IO / POWER 切換**（`Segmented`，與 FailTrayChart 相同的 UX 慣例）：

- IO / POWER 切換（Segmented），共用 `calcTopBalls()` 計算邏輯
- Top 1 Bar 以橘色（`#F5C6A0`）高亮，其餘藍色（`#5BA4D5`）
- 暗色 tooltip（`COLOR_TOOLTIP_BG = '#1A2332'`），不隨主題切換（ECharts tooltip 固定深色）
- X 軸（類別軸）：Ball Name；Y 軸（數值軸）：Fail Count (ea)（原文誤植為「X 軸 Fail Count／Y 軸 Ball Name」且誤寫水平柱狀圖，經比對程式碼 `xAxis.name='Ball Name'`／`yAxis.name='Fail Count (ea)'` 後修正；目前也**沒有**截短 Ball Name 字串長度的邏輯）

#### 資料流

與 FailTrayChart 相同，IO／POWER 兩種 `fail_sample` 資料在使用者按下搜尋時已**一次並行取得並快取**（4 個 HBIN × IO/POWER，共 8 支請求），切換 IO/POWER 只是切換讀取的快取來源，**不會觸發新的 API 請求**：

```mermaid
flowchart TD
    S["搜尋 Lot ID"] --> P["dashboardStore.search\n4 HBIN 並行 × IO/POWER\n共 8 支請求"]
    P --> CI["failSampleCache（IO）"]
    P --> CP["failSamplePowerCache（POWER）"]
    V["Segmented IO/POWER 切換\n（不重新呼叫 API）"] -->|IO| CI
    V -->|POWER| CP
    CI --> FD["failSampleData"]
    CP --> FD
    FD -->|fail_sample| CTB["calcTopBalls\nTop 10 Ball Name"]
    CTB --> EC["ECharts 長條圖\nTop1 橘色／其餘藍色"]
```

### FailTrayChart — Fail Sample on Tray 圖表

以 CSS Grid 繪製 Tray 盤位置圖，每個格子對應一個 DUT 位置，並提供 **IO / POWER 切換**（`Segmented`，與 FailBallChart 相同的 UX 慣例），可分別檢視 IO Pin 與 POWER Pin 的失效分佈。

#### 資料流

IO 與 POWER 兩種資料在使用者按下搜尋時已**一次並行取得並快取**（4 個 HBIN × IO/POWER，共 8 支請求），切換 IO/POWER 只是切換讀取的快取來源，**不會觸發新的 API 請求**：

```mermaid
flowchart TD
    S["搜尋 Lot ID"] --> P["dashboardStore.search\n4 HBIN 並行 × IO/POWER\n共 8 支請求"]
    P --> CI["failSampleCache（IO）"]
    P --> CP["failSamplePowerCache（POWER）"]
    V["Segmented IO/POWER 切換"] -->|IO| CI
    V -->|POWER| CP
    CI --> FD["failSampleData"]
    CP --> FD
    FD -->|fail_sample| DA["computeAnalysis"]
    DA -->|ioPinFailItems + dieResults| BTP["buildTrayPages"]
    FD -->|test_program| TS["fetchTraySpec\n（懶加載，依 test_program 快取）"]
    TS -->|col_count × row_count| BTP
    FD -->|total_qty| BTP
    BTP -->|TrayCell| Grid["CSS Grid Tray 圖"]
```

> **命名提醒**：`computeAnalysis`／`buildTrayPages` 內部變數沿用 `ioPinFailItems`／`ioFailCount` 命名（沿襲自最初只有 IO 版本的時期），但邏輯本身是**通用的 ball_name 非空過濾**：切到 POWER 時傳入的是 `failSamplePowerCache` 的資料，同一套函式直接套用在 POWER Pin 上，並非僅服務 IO，避免依變數名誤解為「只有 IO 有效」。

#### 著色邏輯

| 狀態 | 條件 | 顏色 |
|------|------|------|
| orange | DUT 在 `ioPinFailItems`，且其 ball_name 在 `dieResults.balls`（Top Die Fail） | `#F5C6A0` |
| blue | DUT 在 `ioPinFailItems`，但 ball_name 不在 `dieResults.balls`，或不在 `ioPinFailItems` 的真實 DUT | `#5BA4D5` |
| gray | 超出 `total_qty` 的補位格（dutNo=0） | dark `#2A3F52` / light `#D8E8F4` |

> **設計決策**：真實 DUT 位置（dutNo > 0）不在 ioPinFailItems 時視為藍色（Fail Sample，只是無 ball 資訊），而非灰色。只有超出 total_qty 的補位格才顯示灰色。此邏輯在 IO／POWER 兩種模式下共用，差別只在於「ball_name」對應的是 IO Pin 還是 POWER Pin 名稱。

#### 佈局

```
┌──────────────────────────────────────────────────┐
│ 圖例：橘 = Top 1 Fail  藍 = Fail Sample  灰 = — │
│                                                  │
│  R ┌─────────────────────────────────────────┐  │
│  o │  □ □ □ □ □ □ □      (CSS Grid)          │  │
│  w │  □ □ □ □ □ □ □                          │  │
│  ( │  ...                                    │  │
│  N │                                         │  │
│  ) └─────────────────────────────────────────┘  │
│          Col(N)            ‹ 1 / 3 ›            │
└──────────────────────────────────────────────────┘
```

- Y 軸左側顯示 `Row(N)`（旋轉 -90°）
- X 軸下方顯示 `Col(N)`，右側顯示分頁導航（`‹ 1/N ›`），僅多頁時出現
- 每格 `border: 0px solid colorMode.border`（實際無可見邊框），格線視覺分隔實際來自 CSS Grid `gap: 2px` 造成的底色縫隙

#### Tooltip 主題處理

Ant Design `<Tooltip>` 預設顏色不隨 dark/light 切換。目前作法是**固定使用深色 `color={'#1A2332'}`**（未傳入 `overlayInnerStyle`），刻意不隨主題動態切換，這點與 FailDieChart 的 Tooltip（同樣固定 `COLOR_TEXT_DARK = '#1A2332'`）、以及 FailBallChart/FailDieRateChart 的 ECharts tooltip（固定 `COLOR_TOOLTIP_BG = '#1A2332'`）做法一致：

```tsx
<Tooltip
  title={getTooltipTitle(cell)}
  color={'#1A2332'}
  mouseEnterDelay={0.1}
>
```

> Tooltip 內容目前只顯示 `DUT #N`；原本規劃顯示的 Ball Name／狀態文字（`CELL_LABEL`）已註解保留在程式碼中，未實際渲染。

### 設計討論過程：Tray 著色來源的演進

FailTrayChart 的著色資料來源經歷三個版本的討論修正：

| 版本 | 方法 | 問題 |
|------|------|------|
| v1 | 以 `total_qty` 為格子總數，`fail_sample` 對應位置 | 頁數計算正確但顏色分組邏輯待確認 |
| v2 | 改以展開的 FailSampleList 筆數（per ball_name）計算格子 | 頁數計算結果仍不正確，誤解資料格式 |
| v3（最終） | 回歸 `ioPinFailItems`（來自 `computeAnalysis`）+ `total_qty`，位置對應 `dut_no` | 與產線人員確認後的正確邏輯 |

> **關鍵差異**：FailSampleList UI 會將每個 ball_name 展開為一筆顯示（354 IO 筆 ≠ 354 個 DUT），但 Tray 圖應以「實際 DUT 數量」（`total_qty`）為格子總數，`ioPinFailItems` 僅用於確認哪些 DUT 有 IO fail 紀錄及其 ball_name。

### 圖表卡片標題格式統一

原本所有圖表標題顯示當前 Lot ID（`— 13NFSAB001`），修改為顯示 HBin 類型（`— Short`），讓標題資訊更有意義：

```tsx
// Before
const title = `Fail Ball${currentLotId ? ` — ${currentLotId}` : ''}`;

// After
const title = `Fail Ball${currentHbin ? ` — ${HBinLabel[currentHbin]}` : ''}`;
```

影響元件：`FailBallChart`、`FailDieChart`、`FailDieRateChart`、`FailTrayChart`
