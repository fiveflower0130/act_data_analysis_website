## 技術說明

### 版面與上傳流程

`NetlistUploadPage` 負責主題切換、已上傳清單選取與 Drawer 狀態；`UploadDrawer`
負責檔案選擇、錯誤提示、queue 操作與批次上傳。Drawer 關閉只影響顯示，不清除 queue
或取消進行中的 API request。

### Store 與快取

`uploadStore` 使用 `queues.netlist` 與 `queues['fail-sample']` 保存兩個主題的項目，
沿用最多三個並行工作者。Netlist 預覽資料依 `test_program` 與 Sheet 快取；Fail Sample
成功上傳後仍會呼叫 `dashboardStore.invalidateFailSampleCache()`，並刷新已上傳清單。
rows 查詢則依 batch、Site、q、排序與頁碼快取，重複查看不重新等待 API。
Site 篩選首次取得清單後預設全選；全選時省略 `sites` 參數，全部清除則在前端顯示
「未選取任何 Site」且不發送 rows 請求。Site 顆數／列數由後端必有的 `site_stats`
欄位提供，前端不自行計算；若異常缺漏個別 Site，面板以「—」容錯。

### 預覽資料

Netlist 預覽透過既有及新增 wrapper 懶加載：

- `netlist`
- `test-spec`
- `die-mapping`
- `bin-priority`
- `bin-name`
- `stacking-die`
- `tray`

前端以 `die_pin_raw`（或 `die_pin`）去除最後一個 `.` 後對照 Die Mapping，產生
表格顯示用的 `die_unity`。Fail Sample 明細改由 `/rows` 端點提供 12 欄位資料，
前端採每頁 100 列的後端搜尋／排序／分頁；`fail_reason` 使用主題 danger token 顯示。
